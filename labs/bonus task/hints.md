Условие	Что делает?	Когда используют?
* ```CASCADE```	удаляет дочерние строки	зависимые данные без родителя не имеют смысла
* ```SET NULL```	очищает FK	связь необязательна, история должна остаться
* ```RESTRICT / NO ACTION```	запрещает удаление	связь обязательна
* ```SET DEFAULT```	ставит значение по умолчанию	редкие случаи

### В твоём проекте всё выбрано идеально:
● ```Books``` → ```Authors``` → ```CASCADE```

Если автора удалить — его книги тоже удаляются.

● ```Books``` → ```Categories``` → ```SET NULL```

Категория может быть удалена, книга остаётся.

● ```Borrowings``` → ```Books``` → ```CASCADE```

Если книги больше нет — выдачи тоже удаляются.

● ```Borrowings``` → ```Members``` → ```CASCADE```

● ```Borrowings``` → ```Librarians``` → ```SET NULL```

Выдачи остаются, сотрудник ```NULL```.

## 5. Create Indexes
### Что делает UNIQUE INDEX?

Когда в таблице есть уникальный индекс, PostgreSQL не позволяет вставить строку, в которой значение уже существует в этом индексируемом поле.

То есть уникальный индекс — это как “охранник”, который проверяет:

👉 Есть ли уже такой email?

Если нет → строка вставляется.

Если есть → PostgreSQL выдаёт ошибку и НЕ вставляет запись.

🔥 Пример

Допустим, у тебя уже существует:

``` INSERT INTO members (full_name, email) VALUES ('Ali Serik', 'ali@mail.com'); ```


Теперь ты пытаешься вставить такой же email:

```INSERT INTO members (full_name, email) VALUES ('Dana', 'ali@mail.com');```


Если есть ```UNIQUE INDEX```:

```CREATE UNIQUE INDEX idx_members_email ON members(email);```


То PostgreSQL скажет:

```ERROR:  duplicate key value violates unique constraint "idx_members_email" DETAIL: Key (email)=(ali@mail.com) already exists.```


И строка не попадёт в таблицу.

## 7. Roles and Users 

### Что такое SCHEMA в PostgreSQL?

Схема (schema) — это как папка внутри базы данных.

В ней хранятся:
таблицы
индексы
представления (views)
функции
последовательности (serial / identity)
роли прав доступа

### Что такое public?

В PostgreSQL по умолчанию создаётся схема public,
и все твои таблицы находятся именно там, если ты сам не создавал другие схемы.

То есть:
public = основная схема, в которой находятся все объекты твоей базы

Когда используется SCHEMA public?
Например, когда ты выдаёшь привилегии на ВСЕ таблицы:

```GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO admin;```


Это означает:
``` «Дать роли admin права на ВСЕ таблицы, которые находятся в схеме public».```

То есть ты выдаёшь права не на одну таблицу, а на ВСЮ структуру базы,
которая хранится внутри этой схемы.
